# Hosts

## Layout

```
hosts/
├── cluster.json          how the machines relate to each other
└── <name>/
    ├── host.json         what this machine is          (required)
    ├── secrets.json      sops-encrypted                (required)
    ├── disko.nix         the boot disk                 (required)
    ├── hardware.nix      generated by nixos-generate-config
    ├── storage.nix       additional disks              (optional)
    └── home/             dotfiles, desktop hosts       (optional)
```

The directory name is the host name. `nixosConfigurations.<name>` is created for
every directory containing a `host.json`.

## host.json

### `host`

| Field | Meaning | Read by |
|---|---|---|
| `system` | nixpkgs system string, e.g. `x86_64-linux` | `mkHost` |
| `class` | `"desktop"` or `"server"` | `mkHost`, and gating across `system/`, `server/`, `dev/`, `virt/` |
| `addons` | extra bundles for this machine only | `mkHost` |
| `publicKey` | this machine's ssh host key | `system/ssh.nix` |

`host.name` is derived from the directory and is not stored in the file.

### `user`

| Field | Meaning | Read by |
|---|---|---|
| `name` | login name; `$HOME` is `/home/<name>` | `system/user.nix`, and anything resolving `$HOME` |
| `email` | git identity, and the ACME / authelia contact | `system/git.nix`, `gateway/{proxy,auth}.nix` |
| `publicKey` | the user's ssh key, for commit signing and login | `system/git.nix`, `system/user.nix` |

### `hardware`

| Field | Meaning                                                                          | Read by |
|---|----------------------------------------------------------------------------------|---|
| `gpu` | which vendors are present: `amd`, `intel`, `nvidia`                              | `hardware/common.nix` |
| `modules` | [nixos-hardware](https://github.com/NixOS/nixos-hardware) module names to import | `hardware/common.nix` |
| `busId` | PCI addresses per vendor; needed only for nvidia prime offload                   | `hardware/common.nix` |

### `locale`

| Field | Meaning | Read by |
|---|---|---|
| `timeZone` | tz database name | `system/locale.nix`, `system/system.nix` |
| `default`, `extra` | main locale, and the one used for formats | `system/locale.nix` |
| `xkb.layout`, `xkb.variant` | keyboard layout, console and desktop alike | `system/locale.nix`, `desktop/desktop-environment.nix` |

### `flake`

Absolute path to this repository on that machine.

## cluster.json

Optional.

| Field | Meaning | Read by |
|---|---|---|
| `domain` | the domain services are published under | `gateway/{proxy,auth}.nix`, `desktop/browser/{policies,tabs}.nix` |
| `volumes.<name>.host` | which machine holds this volume | — |
| `volumes.<name>.path` | the mountpoint on that machine | — |
| `members.<host>.addons` | bundles this host runs for the cluster | `mkHost` |
| `members.<host>.ssh.key` | that member's user ssh key | `system/user.nix` |
| `members.<host>.ssh.to` | hosts this member can log in to | `system/user.nix` |
| `members.<host>.syncthing.id` | that member's syncthing device id | `system/syncthing.nix` |
| `members.<host>.syncthing.address` | where to reach it, usually a tailnet address | `system/syncthing.nix` |
| `members.<host>.syncthing.to.<peer>` | folders this member shares with `<peer>` | `system/syncthing.nix` |

`volumes` names the shared stores. A service declares which store it wants, by
name.

Relations are declared once, from the offering side.
`laptop.ssh.to = ["node1"]` puts the laptop's key in node1's
`authorized_keys`. `node1.syncthing.to.laptop = ["vault"]` is read by both ends.

A member is not necessarily a host. `phone` and `win11` appear in
`cluster.json` with no directory under `hosts/`. They take part in relations
without being built from this repository.

## Adding a host

1. `mkdir hosts/<name>`
2. Write `host.json` with at least `host.system` and `host.class`.
3. `nixos-generate-config --no-filesystems --dir /tmp/x` on the target, copy
   `hardware-configuration.nix` to `hosts/<name>/hardware.nix`.
4. Write `disko.nix`.
5. Add the machine's age recipient to `.sops.yaml`, then create `secrets.json`.
6. Optionally add a `members.<name>` entry to `cluster.json`.
